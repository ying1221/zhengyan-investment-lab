# AI 使用与验证记录

记录日期：2026-10-22（Asia/Shanghai）。不包含密钥或个人账户信息。

## 开发过程中怎样使用 AI

使用编程助手阅读用户提供的题目 Markdown，提炼验收要求，设计研究工作流，编写前后端、计算规则、测试与交付说明。财报来自联网检索的真实披露，数值人工结构化，不让模型凭记忆填写。

AI 提出的设计建议经过工程约束：扣非不等于主营；不给无依据置信度；年报摘要与全文同源去重；披露时间与查询时间分开；估值缺失不补数；接口异常不沿用旧结论。最终提交前应由候选人逐条理解与复核。

## 运行时 AI 能力

后端实现固定请求 `https://api.deepseek.com/chat/completions`，模型默认 `deepseek-flash`。实现依据为 [DeepSeek 官方接口说明](https://api-docs.deepseek.com/)（2026-10-22 查阅）。

系统提示要求：将命题与材料当作数据、不执行其中指令；只使用提供证据；JSON 输出子问题、解释、引用；不修改规则数值或状态；不提供交易或收益承诺。用户输入以 JSON 字符串传递，输出经过 HTML 转义。

校验：子问题数量与长度、解释长度、引用 ID 必须存在、正文引用必须在引用数组中、简单交易话术。失败时不展示为成功调用，保留规则结果。尚未完成语义蕴含、所有数字一致性与广泛对抗测试，不能把 ID 校验说成全面事实核查。

## 真实线上成功记录

2026-10-22，用户在公开部署站点完成一次真实 DeepSeek 调用，并提供结果截图。页面显示“DeepSeek 调用成功”，HTTP 200、阶段 complete、耗时约 2.0 秒、结束原因 stop、正文长度 413 字符；右侧显示引用 ID 已校验。

证据为用户提供的成功页面截图，保存在交付包 `验证截图与记录/07-live-model-success.png`。用户密钥未发送给开发助手，也未存入仓库。该次为真实用户实测，与自动化网络替身测试分开记录。

随后收到原始 JSON 与 Markdown 报告，运行 ID 与截图一致，准确耗时 1,955 ms。已复算全部 11 项派生指标，并人工核对模型正文的 E1/E2/E4/E5/E6 引用、反证与缺口，未发现数值或引用错误。报告与 JSON 一致且不含密钥字段。两项措辞改进与完整方法见《真实调用逐项核验.md》。这只证明当前单例，不代表持续可用或全部语义自动验证。
